# 📋 NFC Punch Flow Specification
## מסמך אפיון לוגיקת ניקובי NFC

**תאריך:** 11/12/2025  
**גרסה:** 1.0  
**סטטוס:** טיוטה לאישור

---

## 1. 🎯 מטרת המסמך

מסמך זה מגדיר את הלוגיקה המלאה לניקוב באמצעות NFC, כולל:
- חלוקת אחריות בין הקליינט לאדמין
- מסננות (Filters) בכל צד
- ערוצי תקשורת ושדות נדרשים
- מקורות נתונים והזרקת מידע

---

## 3. 🔍 מסננות צד קליינט (Client-Side Filters)

הקליינט אחראי על המסננות הבאות **לפני** שליחה לאדמין:

| # | מסננת | תנאי | פעולה | הודעה |
|---|-------|------|-------|-------|
| F1 | **ניקוב ידני** | `punch_mode === 'manual'` | חסום | הודעה בנוסח שסופק ע"י המפתח |
| F2 | **תג NFC לא מזוהה** | `nfc_string` לא נמצא | חסום | "תג NFC לא מזוהה" |
| F3 | **לקוח לא שייך לעסק** | אין כרטיסיות לעסק זה | חסום | "אין לך כרטיסייה פעילה בעסק זה" |
| F4 | **בחירת כרטיסייה** | >1 כרטיסיות פעילות | השהה | הצג מסך בחירה, המשך אחרי בחירה |
| F5 | **הגעה למקסימום** | `used_punches >= total_punches` | הודע לאדמין | הודעה + שידור לאדמין |
| F6 | **אין כרטיסייה פעילה** | 0 כרטיסיות | חסום | "אין כרטיסייה פעילה" |

### 3.1 סדר הפעלת המסננות:

```
סריקת NFC
    │
    ▼
[F2] תג מזוהה? ─── לא ──► הודעת שגיאה, עצור
    │ כן
    ▼
[F1] punch_mode === 'manual'? ─── כן ──► הודעת חסימה, עצור
    │ לא
    ▼
[F6] יש כרטיסיות פעילות? ─── לא ──► הודעת שגיאה, עצור
    │ כן
    ▼
[F3] כרטיסיות שייכות לעסק? ─── לא ──► הודעת שגיאה, עצור
    │ כן
    ▼
[F4] כמה כרטיסיות? ─── >1 ──► הצג מסך בחירה
    │ 1                        │
    ▼                          ▼ (לאחר בחירה)
[F5] הגעה למקסימום? ─── כן ──► הודע לאדמין + שדר
    │ לא
    ▼
שידור לאדמין (punch_requests)
```

## 4. 🔍 לוגיקת צד אדמין (Admin-Side Logic)

האדמין מקבל את כל הניקובים שעברו את המסננות של הקליינט ומבצע:

| # | פעולה | תנאי | תוצאה |
|---|-------|------|-------|
| A1 | **בדיקת מצב** | `punch_mode` | ידני: הודעה, חצי-אוטו: מודאל, אוטו: ביצוע |
| A2 | **בדיקת כרטיסייה מלאה** | `used_punches >= total_punches` | דיאלוג חידוש |
| A3 | **ביצוע ניקוב** | - | עדכון `PunchCards`, לוג, צליל |
| A4 | **בדיקת ניקוב מזכה** | `new_punches >= total_punches` | דיאלוג הטבה |
| A5 | **שליחת הודעה ללקוח** | - | Push notification |
| A6 | **עדכון סטטוס** | - | `punch_requests.status = 'completed'` |

### 4.1 זרימת לוגיקה באדמין (זהה לברקוד):

```
קבלת punch_request מ-Realtime
    │
    ▼
[A1] בדיקת punch_mode:
    ├── manual ──► הודעת חסימה (לא אמור להגיע כאן!)
    ├── semi ──► פתיחת מודאל ניקוב
    └── auto ──► המשך לביצוע
    │
    ▼
[A2] כרטיסייה מלאה? ─── כן ──► דיאלוג "חדש ובצע ניקוב"
    │ לא
    ▼
[A3] ביצוע ניקוב:
    ├── עדכון PunchCards.used_punches
    ├── הוספה ל-activity_logs
    ├── השמעת צליל הצלחה
    └── עדכון state מקומי
    │
    ▼
[A4] הגיע לניקוב מזכה? ─── כן ──► דיאלוג "הגיע להטבה"
    │ לא
    ▼
[A5] שליחת הודעה ללקוח (Push)
    │
    ▼
[A6] עדכון punch_requests.status = 'completed'
```

## 5. 📡 ערוץ התקשורת: טבלת `punch_requests`

### 5.1 מבנה הטבלה:

| שדה | סוג | מקור | תיאור |
|-----|-----|------|-------|
| `id` | uuid | אוטומטי | מזהה ייחודי |
| `business_code` | varchar | קליינט | קוד העסק (מ-nfc_string) |
| `customer_phone` | varchar | קליינט | טלפון הלקוח המחובר |
| `card_number` | varchar | קליינט | מספר הכרטיסייה (למשל: "0002-0544515199-1234") |
| `product_name` | varchar | קליינט | שם המוצר |
| `is_prepaid` | boolean | קליינט | האם משולם מראש |
| `status` | varchar | קליינט→אדמין | pending→completed/rejected |
| `created_at` | timestamp | קליינט | זמן יצירה |
| `resolved_at` | timestamp | אדמין | זמן טיפול |
| `resolved_by` | varchar | אדמין | admin/auto |

### 5.2 הערה - שדות קיימים:

**לא נדרש שדה נוסף!** כל המידע הנדרש כבר קיים:

| מידע | מקור | טבלה |
|------|------|------|
| ניקובים נוכחיים | `used_punches` | `PunchCards` |
| סה"כ ניקובים | `total_punches` | `PunchCards` |
| האם הגיע למקסימום | מחושב: `used_punches >= total_punches` | - |
| מקור הניקוב | `source` | `activity_logs` |

## 6. 📥 מקורות נתונים (Data Sources)

### 6.1 נתונים שהקליינט שואב:

| נתון | טבלה | שדה | שאילתה |
|------|------|-----|--------|
| קוד עסק | `businesses` | `business_code` | `WHERE nfc_string = ?` |
| מצב ניקוב | `businesses` | `punch_mode` | `WHERE nfc_string = ?` |
| כרטיסיות לקוח | `PunchCards` | * | `WHERE customer_phone = ? AND business_code = ? AND status = 'active'` |
| פרטי מוצר | `products` | `product_name` | `WHERE product_code = ?` |

### 6.2 נתונים שהאדמין שואב:

| נתון | טבלה | שדה | שאילתה |
|------|------|-----|--------|
| פרטי לקוח | `customers` | `name` | `WHERE customer_phone = ?` |
| פרטי עסק | `businesses` | `name, punch_mode` | `WHERE business_code = ?` |
| הטבה | `PunchCards` | `benefit` | `WHERE card_number = ?` |

## 7. 🔄 זרימת מידע מלאה (End-to-End Flow)

```
┌────────────────────────────────────────────────────────────────────────────┐
│                           PHASE 1: סריקה וזיהוי                             │
├────────────────────────────────────────────────────────────────────────────┤
│  CLIENT:                                                                    │
│  1. סריקת תג NFC → קבלת nfc_string                                         │
│  2. שאילתה: SELECT business_code, name, punch_mode                         │
│             FROM businesses WHERE nfc_string = '{value}'                   │
│  3. אם לא נמצא → הודעת שגיאה, עצור                                         │
└────────────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌────────────────────────────────────────────────────────────────────────────┐
│                           PHASE 2: מסננות קליינט                            │
├────────────────────────────────────────────────────────────────────────────┤
│  CLIENT:                                                                    │
│  1. אם punch_mode === 'manual' → הודעת חסימה, עצור                         │
│  2. שאילתה: SELECT * FROM "PunchCards"                                     │
│             WHERE customer_phone = '{phone}'                               │
│             AND business_code = '{code}' AND status = 'active'             │
│  3. אם 0 כרטיסיות → הודעת שגיאה, עצור                                      │
│  4. אם >1 כרטיסיות → הצג מסך בחירה                                         │
│  5. בדוק אם used_punches >= total_punches → סמן is_at_max = true           │
└────────────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌────────────────────────────────────────────────────────────────────────────┐
│                           PHASE 3: שידור לאדמין                             │
├────────────────────────────────────────────────────────────────────────────┤
│  CLIENT:                                                                    │
│  INSERT INTO punch_requests (                                               │
│    business_code, customer_phone, card_number, product_name,               │
│    is_prepaid, status, created_at                                          │
│  ) VALUES (                                                                 │
│    '{business_code}', '{phone}', '{card_number}', '{product_name}',        │
│    {is_prepaid}, 'pending', NOW()                                          │
│  );                                                                         │
└────────────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼ Supabase Realtime
┌────────────────────────────────────────────────────────────────────────────┐
│                           PHASE 4: טיפול אדמין                              │
├────────────────────────────────────────────────────────────────────────────┤
│  ADMIN:                                                                     │
│  1. קבלת הבקשה דרך Realtime subscription                                   │
│  2. בדיקת punch_mode (ידני/חצי/אוטו)                                       │
│  3. בדיקת כרטיסייה מלאה → דיאלוג חידוש                                     │
│  4. ביצוע ניקוב: UPDATE "PunchCards" SET used_punches = used_punches + 1   │
│  5. לוג: INSERT INTO activity_logs (...)                                   │
│  6. צליל הצלחה                                                              │
│  7. בדיקת ניקוב מזכה → דיאלוג הטבה                                         │
│  8. שליחת Push ללקוח                                                        │
│  9. UPDATE punch_requests SET status = 'completed'                         │
└────────────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼ Supabase Realtime
┌────────────────────────────────────────────────────────────────────────────┐
│                           PHASE 5: אישור ללקוח                              │
├────────────────────────────────────────────────────────────────────────────┤
│  CLIENT:                                                                    │
│  1. האזנה לעדכון status ב-punch_requests                                   │
│  2. אם status === 'completed' → הצג אישור ניקוב, עדכן UI                   │
│  3. אם status === 'rejected' → הצג הודעת שגיאה                             │
└────────────────────────────────────────────────────────────────────────────┘
```

## 8. 📋 שאילתות SQL מרכזיות

### 8.1 קליינט - זיהוי עסק:
```sql
SELECT business_code, name, punch_mode 
FROM businesses 
WHERE nfc_string = '{scanned_nfc_string}';
```

### 8.2 קליינט - שליפת כרטיסיות:
```sql
SELECT 
  card_number, 
  product_code, 
  used_punches, 
  total_punches, 
  prepaid, 
  benefit, 
  status
FROM "PunchCards"
WHERE customer_phone = '{phone}'
  AND business_code = '{business_code}'
  AND status = 'active';
```

### 8.3 קליינט - שידור ניקוב:
```sql
INSERT INTO punch_requests (
  business_code, 
  customer_phone, 
  card_number, 
  product_name, 
  is_prepaid, 
  status, 
  created_at
) VALUES (
  '{business_code}',
  '{customer_phone}',
  '{card_number}',
  '{product_name}',
  {is_prepaid},
  'pending',
  NOW()
);
```

### 8.4 אדמין - עדכון סטטוס:
```sql
UPDATE punch_requests 
SET status = 'completed',
    resolved_at = NOW(),
    resolved_by = 'admin'
WHERE id = '{request_id}';
```
